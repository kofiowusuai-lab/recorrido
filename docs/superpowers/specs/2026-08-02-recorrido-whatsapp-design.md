# Recorrido — WhatsApp-native listing content for LatAm real estate agents

**Status:** Design approved, pending spec review
**Date:** 2026-08-02
**Working name:** Recorrido (naming still open)

---

## 1. Problem

LatAm real estate agents run their entire business inside WhatsApp. They win listings, answer buyers, and send photos from a phone. Their listing media is weak: dim phone photos, empty rooms with no furniture, copy-pasted descriptions, and no video. Video listings reach far more buyers than photo-only listings, but hiring a videographer in Bogotá costs roughly USD 150 and takes three days, so most listings never get one.

Every existing tool solving adjacent problems fails the same way. It is a web app, in English, requiring account creation, a dashboard, and a USD credit card. A Bogotá agent has a phone, WhatsApp, and Nequi.

**The gap is not the technology. It is delivery and payment rails.**

### Why we win

We already hold verified WhatsApp numbers and emails for RE/MAX agents across Colombia (137 in Bogotá across 12 offices, with 12 named Bróker/Owner contacts and direct mobiles) and Argentina (7,107 agents, 100% phone and email coverage). We also hold their live listing photos.

That last point is the entire go-to-market. The first cold message contains the agent's own property, remade, free, before we ask for anything.

| **Recorrido cinematográfico 60-90s** | Per-room camera moves, Spanish voiceover, music, captions, branded intro/outro |

### Positioning: recorrido, never "tour 3D"

A spatially continuous walkthrough (through a doorway, around a corner) requires Gaussian splatting trained on overlapping video capture. Listing photos will not produce it.

What we deliver is a **cinematic recorrido**: each room gets a real camera move generated by image-to-video (slow push into the kitchen, orbit around the island, crane rise over the terraza), cut together with match transitions. It looks premium. It is not a walkthrough.

All marketing says *recorrido cinematográfico*. Never *tour 3D*, never *recorrido virtual 360*. Overclaiming here is both a legal exposure under Ley 1480 and a trust failure in a market where agents talk to each other constantly.

**Future upgrade path:** ask the agent to shoot one slow 60-second phone video. Zero new skill required, they already do this. That input unlocks genuine Gaussian splatting and becomes a higher tier later. Out of scope for v1.

## 3. Architecture

```
WhatsApp Cloud API
      │  (agent sends photos — opens 24h service window)
      ▼
  Intake service ──► media download, dedupe, job creation
      │
      ▼
  Postgres queue (Supabase, SELECT … FOR UPDATE SKIP LOCKED)
      │
      ▼
  Worker pool ──► leases credential ──► RenderBackend
      │                                   ├── grok_cli   (GROK_HOME isolated)
      │                                   ├── codex_cli  (images)
      │                                   └── xai_api    (failover / production)
      ▼
  QA gate ──► structural drift check, reject + regenerate
      │
      ▼
  Assembly (ffmpeg) ──► stitch, VO, music, captions, branding
      │
      ▼
  Delivery back to WhatsApp (inside 24h window)
```

### 3.1 Intake

WhatsApp Cloud API, official. The compliance shape is favourable: the customer messages **us** first, which opens a 24-hour customer service window permitting free-form replies with no template approval. The entire delivery flow lands inside that window.

Templates are needed only for re-engagement past 24 hours: renewal reminders, quota warnings, and "tu recorrido está listo" when a job outruns the window. Register three templates at launch.

### 3.2 Job model

A recorrido is a parent job fanning out to independently schedulable children. This is what makes a worker pool useful and what lets a failed clip retry without redoing the job.

```
job (recorrido)
 ├── task: clip × 12       ← any worker, any credential, independently retryable
 ├── task: vo              ← ElevenLabs Spanish
 └── task: assemble        ← depends on all clips + vo
```

Clip count derives from target runtime: a 60-second recorrido is 12 clips of 5 seconds, a 90-second recorrido is 18. One clip per camera move, one to three moves per room. Clip length is a per-job parameter, not a constant, since backend maximums differ.

Queue is Postgres `SELECT … FOR UPDATE SKIP LOCKED` on the existing Supabase project. No new infrastructure.

### 3.3 Credential pool

Workers do not hold credentials. They lease one per task from a pool, so adding account #2 is inserting a row.

```sql
create table credentials (
  id                   uuid primary key default gen_random_uuid(),
  backend              text not null check (backend in ('grok_cli','codex_cli','xai_api')),
  grok_home            text,            -- isolated state dir; null for api backends
  api_key_ref          text,            -- vault reference; never the key itself
  state                text not null default 'healthy'
                       check (state in ('healthy','cooling','throttled','dead')),
  observed_cap         int,             -- learned daily ceiling, null until discovered
  used_today           int not null default 0,
  reset_at             timestamptz,
  cooldown_until       timestamptz,
  consecutive_failures int not null default 0,
  last_error           text,
  created_at           timestamptz not null default now()
);
```

**Adaptive capacity discovery.** Consumer daily limits are undocumented and change without notice. Hardcoding a constant guarantees it goes stale. Instead workers record throttle events and back off exponentially, and `observed_cap` converges on each account's real ceiling from observed behaviour.

**Isolation, verified.** `GROK_HOME=/opt/render/accounts/acct-NN` produces a fully separate state directory with its own `auth.json`, `config.toml`, and distinct `agent_id`. Confirmed working on this machine at grok CLI 0.2.112.

### 3.4 Circuit breaker

This bounds the failure mode with no recovery.

- **Per credential:** 3 consecutive auth or quota failures marks it `dead` and alerts.
- **Pool-wide:** more than 40% of credentials unhealthy inside 60 minutes indicates a correlated ban wave rather than bad luck. The system auto-flips `RENDER_BACKEND` to `xai_api`, drains the queue through the paid API, and pages the operator.

**A small prepaid xAI API balance stays warm permanently.** It costs a few dollars a month sitting idle and converts an account loss from a business-ending event into an expensive Tuesday. This is non-negotiable and ships in v1, not later.

### 3.5 Render backend abstraction

One interface, three implementations, selected by config:

```
RenderBackend
  .image_enhance(src, opts)  -> path
  .image_stage(src, opts)    -> path
  .image_to_video(src, prompt, opts) -> path
  .health()                  -> healthy | throttled | dead
```

Backend resolution has two levels, and they do not conflict. Each credential row carries its own `backend`, so a heterogeneous pool is normal: consumer accounts handle baseline while an API credential absorbs overflow. `RENDER_BACKEND` is the global **default preference** the scheduler uses when choosing which healthy credential to lease next.

`RENDER_BACKEND=grok_cli` at launch, `xai_api` in production. The circuit breaker flips this default, which drains the queue through API credentials without touching worker code. Switching is a config flip, not a rewrite.

This layer also restores `grok_imagine.py`, currently a dead reference in the `ugc-video-producer` and `ugc-minimax-mode` skills after `~/.openclaw/scripts/` was lost. It must reproduce the documented behaviour: pin `-m grok-build`, `--max-turns 16`, 600s timeout, and harvest-and-retry covering the known ~42% silent-fail rate on the wrong model.

### 3.6 QA gate

Image-to-video models invent geometry. Push a camera toward a doorway and the model hallucinates a hallway the apartment does not have. In real estate that is misleading advertising under Ley 1480.

Two guardrails:

1. **Prompt constraint.** Camera motion only. Dolly, pan, orbit, crane. No scene generation, no object insertion, no architectural change.
2. **Structural drift check.** Compare the generated clip's first and last frames against the source photo. Reject and regenerate on room-geometry change. Failure modes are already catalogued in `ugc_qa_bank.md`.

Regeneration costs margin. It is cheaper than the alternative.

### 3.7 Assembly

ffmpeg at `~/bin/ffmpeg`. Stitch clips with match cuts, lay Spanish voiceover (ElevenLabs), music bed from a licensed library, burned captions, agent branding card built from scraped office and contact data, and the `Imagen con ambientación virtual` label on staged stills.

## 4. Capacity and scaling triggers

| Accounts | Sustainable clips/day | Recorridos/day | Practical customers | Recorrido SLA |
|---|---|---|---|---|
| 1 | 30-40 | ~3 | **8-10** | ~26 min |
| 3 | 90-120 | ~9 | ~25 | ~12 min |
| 6 | 180-240 | ~18 | ~50 | ~8 min |

**Trigger: stand up account #2 at 8 paying customers.** Past that, serial queueing during business hours degrades the SLA faster than the daily cap binds.

**Trigger: migrate to `xai_api` at 20 paying customers.** At 20 Profesional customers revenue is $980/mo against roughly $252/mo of API COGS at $3.15 per recorrido. The API becomes affordable at precisely the point consumer-account risk becomes unacceptable. Revenue funds the migration.

## 6. Go to market

### Broker-first motion (primary)

We hold 12 named Bróker/Owner contacts in Bogotá with direct mobiles. Selling Oficina to one broker converts 10 to 30 agents in a single conversation, at 3x the ACV, with the broker running onboarding for us.

Agent-by-agent outreach is the fallback for offices whose broker declines.

### The cold open

Before any pitch, we generate a free recorrido from the agent's own live listing photos, which we already hold. The first WhatsApp message is their property, remade. Nothing else converts comparably on cold outreach.

### Compliance on outreach

Colombian Ley 1581 de 2012 (habeas data) covers personal data including a mobile number identifying a natural person, business context notwithstanding. Every outreach message carries a clear opt-out, opt-outs are honoured permanently and recorded, and the contact database is registered with the RNBD where thresholds require it.

## 7. Risks

| Risk | Mitigation |
|---|---|
| Correlated ban across account pool | Pool-wide circuit breaker, warm API balance, auto-failover |
| Model hallucinates geometry, agent misrepresents property | Camera-motion-only prompts, structural drift QA gate, regenerate on fail |
| Consumer ToS: no reselling the Service, no automated access above human rate | Staged backend, migrate to paid API at 20 customers, breaker bounds blast radius |
| Commodity pressure from English virtual-staging tools at $16/mo | Moat is WhatsApp delivery, Spanish output, local payment rails, and portal-specific SEO copy, not the model |
| Churn once agent has "enough" content | Quota resets monthly against real listing velocity; upsell the 24/7 lead responder as the second product |
| Agent-supplied photos too poor to enhance | Intake quality check with a plain-Spanish reshoot instruction reply |
